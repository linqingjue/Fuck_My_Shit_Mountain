# Maintainability Audit Prompt（可维护性审计提示词）

使用 fuck-my-shit-mountain skill 的 **maintainability mode**。

共享设置、覆盖策略、报告模板、HTML 和 lint 规则位于 `references/report-format.md`；生成报告前必须加载该引用。

## 聚焦范围

只报告会显著增加理解成本、修改成本、测试成本或缺陷概率的可维护性问题。不要把个人风格偏好写成风险。

## 审计区域

### 复杂度
- 函数、类、模块是否过长、分支过多、嵌套过深？
- 是否存在难以局部理解的隐式控制流？

### 耦合
- 一个改动是否会牵连大量无关文件？
- 模块之间是否通过全局状态、共享可变对象或隐式约定耦合？

### 重复
- 是否存在必须同步修改的重复逻辑？
- 重复是合理的局部清晰，还是会导致行为分叉？

### 命名与一致性
- 命名是否误导真实行为？
- 同一概念是否有多个名称，或多个概念共用一个名称？

### 文档与注释
- 注释是否解释原因，而不是重复代码？
- 文档是否过期、缺失或与行为冲突？

## 规则

1. 可维护性发现必须说明未来某类修改为什么会更容易出错。
2. 不要建议“大重构”，除非局部修复无法降低风险。
3. 优先给出小步整理：提取函数、拆分职责、收口边界、消除误导命名、补充关键文档。
4. 每条发现都要有回归测试或重构保护建议。
